# Events references

Knowledge about the events stage that the code doesn't show: why things are the way they
are, what constrains them, what's been measured, and what tends to go wrong.

These are **not a mirror of the code**. Don't describe functions, signatures, file
layouts or control flow here; read the code for that. If something can be learned by
reading the code, it doesn't belong here.

| File | Holds |
|---|---|
| [stack.md](stack.md) | Models and libraries, why they were chosen, what each expects |
| [decisions.md](decisions.md) | Design decisions and their rationale, including rejected options |
| [pitfalls.md](pitfalls.md) | Non-obvious traps and how to avoid them |
| [tuning-log.md](tuning-log.md) | Eval results per change: what was tried and what it did |

Add a new file when a topic doesn't fit these; list it in the table above.
